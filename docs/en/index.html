The AI lab

The lab examines what AI agents can do in a company today and under which conditions they can be allowed to work.

A whole company as test bed

The simulated Muster AG is a Swiss industrial business. It has two years of business data: customers, suppliers, orders, accounting and closings.

Proven and new

The lab tests proven methods and new approaches that are not yet established in practice. Every test has expected results and built-in traps.

Continuously evolving

The lab is used and extended every day. New use cases are added continuously, and quality and cost are measured for each.

Note: Muster AG is a fictional company. All companies, people and figures in the lab are made up.

What the agent handles today

The agent works on request in chat and autonomously on schedules. It has read access to the entire ERP.

Payables

Supplier invoices

Read documents, match suppliers, propose account assignments, flag anomalies.

Sales

Customer quotes

A request becomes a quote in the ERP, with prices and terms from master data.

Controlling

Monthly reports and KPIs

Key figures with a fixed calculation, with commentary for management.

Analytics

Analysis and research across the ERP

Questions in natural language, answers from sales, purchasing and accounting data.

Inbox

Email management

Classify every email, handle requests, detect and escalate anything suspicious.

Security

Resistance to manipulation

The agent recognises deception attempts in emails and documents and reports them.

Governance and principles

An agent needs fixed rules before it may work in a company. These apply in the lab:

  1. Least privilege

    The agent reads the ERP and the mailbox with access that can only read. Permissions live in the target system, not in the prompt.

  2. Tool-based access via MCP

    Anything that changes data runs through a dedicated tool server with narrow, validated tools. There is no other way to write.

  3. Human-in-the-loop

    Consequential actions need approval by button, which the agent cannot trigger itself. A “yes” in the chat does not count.

  4. Content is not a command

    Whatever an email or document says is material. The agent does not follow instructions inside it, it reports them.

  5. Semantic layer

    Fixed definitions and calculations, so the agent answers the same question the same way every time.

  6. Versioned skills with release

    Domain knowledge lives in skills under version control. Changes go live only after review, including those the agent proposes itself.

  7. Vendor-agnostic

    ERP, mailbox and language model are replaceable building blocks. The business logic does not depend on any single product.

Research

open questions
  • Multi-agent organisation: agents run functions
  • Synthetic business world: agents act as customers and suppliers
  • Learning loop: the agent proposes improvements, a human releases them
